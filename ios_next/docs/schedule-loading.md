# 课表加载与兼容性核查

## 当前数据链路

`NativeScheduleStore` → 已登录 WKWebView 的数据桥 → `/api/jwxt/schedule` → 本地教务客户端或远端 Agent → 学校 HTML → `jwxtParser` → 课程规则 JSON → 客户端缓存及周次筛选。

学校 Cookie 和 HTML 解析留在服务端。JSON 已含星期、大节／小节、课程名、老师、地点、原始周次和 `weekList`，包括单双周信息。客户端只需应用修改记录并根据选中周筛选，不需要反复下载、解析学校页面来生成每个周视图。

## 核查依据

- `server/src/services/jwxtFacade.ts` 的原查询通过 `xskb_list.do?viweType=0` 取页面，数字周次放入 `zc`；原来不区分“明确请求全部周”与“不传周次”。
- `server/tests/jwxtParser.test.ts` 的教务页面样例存在 `<option value="">(全部)</option>`；通用选项解析器原来跳过空值，导致丢失范围信息。
- `jwxtParser` 已解析课程周次、单双周、小节、跨行表格和重复课程，不必将整套 HTML 解析器再移植至 Swift。
- 合入远端更新后，页面与小组件经 `scheduleData` 按会话／学期／周次共享 5 分钟缓存，强刷写回共享结果；整学期 `all` 使用独立缓存键，不覆盖小组件的数字周次缓存。逐周强刷仍会放大学校请求量。
- 原生 `blocks(for:result:)` 已按 `weekList` 做本地周次筛选。

这些是源码和测试样例证据，未使用真实学校账号确认当前线上“全部周”行为；不能据此宣称已经完成实时教务联调。

## 最终实现

优先用 `week=all` 查询，服务端显式传 `zc=`。解析返回页面的周次选择器，仅实际选择“全部”时声明 `scope: semester`；数字周次是 `week`，无法判定则为 `unknown`。客户端仅对已确认整学期的数据建立完整学期缓存。

学校返回单周时，先显示当前周，再延迟 300ms 开始后台补齐，一次一个后台查询，优先下一周、上一周，再向两侧扩展。每周完成即推送原生缓存，不必等待整个学期；缓存命中切周仅本地处理，并通知 Web 桥调整预取优先级。前台与后台共享同一周的进行中请求，成功结果保留，失败不清除当前显示。完整后合并并推送原生缓存。前台已经选择其他周时，后台结果不会改写选中周。切账号清空缓存，切学期停止旧学期下一次后台请求。

首次课表响应后，校历和修改记录并行读取。Web 桥最多保留 4 个学期，完整后丢弃逐周副本；缓存 12 小时，暂不跨进程持久化。客户端规则计算量由课程数量决定，不再随每次切周增加学校请求。

## 请求量比较

以下是代码路径推导与模拟接口计数，不是生产延迟实测。假设本科 20 个教学周，单次课表请求成功，不计登录恢复与 Modern→Legacy 回退：

| 路径 | 首次显示前的课表查询 | 切周查询 |
| --- | --- | --- |
| 上一版阻塞式整学期补齐 | 约 20 次 | 缓存命中为 0 |
| 已确认“全部周”的规则直取 | 1 次 | 缓存命中为 0 |
| 学校仅返回单周／旧服务端回退 | 通常 1–2 次；必要时补查当前周 | 已缓存为 0，缺失周与后台共用请求 |

首屏另需校历与修改记录各一次，二者并行。回退模式仍可能需要查询所有教学周，总流量并不会凭空消失；它改善的是首屏等待、重复请求和失败恢复。只有学校确实返回完整规则时，才能把整学期学校查询降为一次。

显式刷新时，规则查询绕过服务端缓存；老服务端不支持该请求时，恢复原单周请求可能再强刷一次。后台补齐始终使用服务端缓存，不按教学周反复强刷。

## 兼容边界

| 组合 | 行为 |
| --- | --- |
| 旧 Web／iOS／Android + 新服务端 | 数字周次及省略周次的含义不变；仅新增可选 `scope` 字段 |
| 新 iOS + 旧服务端／旧 Agent | 缺少 `scope` 或拒绝 `all` 时重走旧单周参数；本次桥生命周期记住能力，避免每次重复探测 |
| 新 iOS + 旧数据桥 | `completeSemester` 缺省为 false，继续单周缓存；新增后台推送是可选能力 |
| 旧 iOS + 新数据桥 | 保留 `version: 1` 和原函数参数／响应结构；额外字段可忽略，后台推送使用可选调用 |
| 不明范围或没有教学周列表 | 不推断完整学期；保留可用单周数据 |
| 授权失效 | 不将其当作“不支持 all”而反复回退请求 |
| 后台失败／账号切换／刷新竞争 | 不发布部分整学期，不让旧账号或较旧快照覆盖新数据 |

服务器与 Agent 更新后才能走已验证范围的规则直取路径；在此之前客户端正常回退。没有执行推送或生产部署。

## 验证

服务端解析／SSO／小组件测试 52 项通过；Web／随包桥兼容测试 19 项通过；原生缓存与标签切换检查通过，iOS 模拟器构建和 Web 类型检查通过。

服务端全量 `tsc --noEmit` 未通过：未修改的 QQ Bot、图片、云存储模块存在缺失依赖及相关类型错误。真实教务登录、全部周行为与真机签名环境仍需联调验证。
