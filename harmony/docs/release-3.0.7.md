# HarmonyOS 3.0.7（27）发布包

包名 `cn.lizmt.cpuweb`，应用清单、入口版本参数与 User-Agent 为 3.0.7（27）。沿用既有发布证书和 Profile，历史导出包保留。

## 更新内容

相对 3.0.6（26）：

- 课表显示设置（课表风格页里，只作用于周视图，默认值保持原来的样子）：
  - 课程格子：格子高度（70%–180%）、文字大小（小／标准／大）、紧凑排版、显示老师、显示非本周课程。
  - 课表网格：显示节次时间、高亮当前节次（原来的「标出当前时间」）、显示回到本周按钮、显示周六、显示周日、周日排在首列。
  - 原来的「显示周末」拆成周六、周日两个开关，旧值会带过来。关掉的那一天有课或调休时仍会显示。
  - 「周日排在首列」时，第一列是周一前一天的那个周日，属于上一个教学周。这一列的课只能看，要切到上一周才能编辑，也不能在这一列添加课程。
  - 「非本周课程」只在拿到整学期课表时才有，淡显在本周空着的节次里；放假和调课的那一天不填。点开只能看，不能编辑。
- 月视图：
  - 在月历上上下拖动换月，格子跟着手指走，拖过一段距离翻到下一个月或上一个月，不够就弹回去。一次翻一个月。
  - 日期下面的一串彩色圆点改成一条：一节课是一个点，课越多越长，四节以上到头，用主题色。表格风格仍然在格子里写课名。

- 客户端统计上报（后台「鸿蒙客户端」页的数据来源）：站点页面加载完成时上报一次，半小时内不重复。内容是本机生成的随机安装编号（只存在应用自己的首选项 `native_client_stats` 里）、设备品牌、型号、设备类型、系统版本和 API 版本、应用版本，以及外观模式、课表风格、课程配色、是否用了课表背景、是否改过显示设置。不读取 OAID、UDID 等设备标识。请求带着网页的登录会话，所以登录后的上报能对上账号。没有崩溃和性能数据。

规则与网页 `displaySettings.ts`、安卓 `ScheduleDisplayRules` 相同；iOS 的同一批改动见 `ios_next/docs/release-4.14.md` 之后的记录。

## 服务端依赖

- 显示设置只保存在设备上（`native_schedule_style` 首选项），不依赖服务端。
- 统计上报发往 `POST /api/app-clients/harmony/heartbeat`，由提交 `629a3d8a` 加入（新表 `HarmonyClientInstall`、`HarmonyClientDailyActive`）。服务端没有部署这个提交时，上报得到 404，应用不受影响，后台页面没有数据。

## 上架前要确认的事

站点的隐私政策（`web/public/privacy.html`）里没有写客户端会上报设备型号、系统版本这类信息；iOS 和安卓的原生客户端已经在上报同样的内容。这一版给鸿蒙加了上报，提交审核前由账号持有人决定是否先补隐私政策和 AppGallery 的隐私声明。条款正文没有改动。

本版打了两次包。第一次（`output/harmony-3.0.7/`，提交 `c94715bd`）不带统计上报，已被第二次（r2）取代，没有提交过审核。两次的签名包都在模拟器上跑过冒烟；模拟器上原来已经装着 3.0.7 的第一份包，所以 `phone-smoke/results.json` 里记的「此前安装的版本」是 3.0.7。

显示设置和月视图使用隔离的验收包（`cn.lizmt.cpuweb.scheduleqa`，离线数据，实际原生课表组件），在版本提交之前的源码上完成；之后的提交只改了版本号和加了统计上报。验收数据里的课程都是每周都上，看非本周课程时临时把几门课改成了只在双周上。设置页（`Index.ets` 里的开关、滑杆和首选项读写）不在验收包里，只经过编译，没有在设备上点过。设备为手机模拟器，1080 × 2340，360 vp 宽。

未验证：统计上报的实际请求（冒烟只到游客的登录页，确认了加上报后启动正常；没有对着部署了新接口的服务端发过一次真实上报，后台页面也只经过类型检查，没有在浏览器里打开过）；设置页的实际操作和重启后设置是否保留；真实账号登录线上站点后的完整应用；周日首列在学期第一周和跨调休日时的真机表现；平板；读屏；真机；本版没有再跑 14 组课表交互脚本和「真实外壳对接本机示例站点」。
