# 药大拾间 Android 客户端

与新版 iOS（`ios_next`）和 HarmonyOS 客户端结构一致的原生外壳：Jetpack Compose 负责底部五栏、原生顶栏、登录与课表等高频交互；首页、教务、服务、我的及其子页面继续用同一个 WebView 加载现有站点。包名 `cn.lizmt.cpuweb`，最低 Android 7.0（API 24）。构建版本以 `app/build.gradle` 为准，线上版本以 `../server/src/releases/android.json` 为准。

打包、签名、上传或发布前，请先读 [Android 发布操作手册](../docs/android-release-runbook.md)，不要根据本 README 的本地编译示例直接分发 APK。

## 原生能力

- **外壳**：Compose 底部导航（首页、教务、课表、服务、我的），默认进入原生课表。Web 栏目使用原生顶栏：根页面显示 Logo 与标题，子页面显示返回键与网页路由标题；右侧为刷新、消息（未读角标）或登录、快捷入口面板（发帖、消息、管理后台、客户端下载、论坛、公告、教务、课表、服务、二手、拾间 AI 与外观切换）。帖子详情等自带导航的页面隐藏原生顶栏和底栏；键盘弹出时隐藏底栏；首页提供原生“投稿”按钮。
- **共享 WebView**：所有 Web 栏目共用一个 WebView，保留 Cookie、DOM 存储、站内路由；网页顶栏和底栏由注入样式隐藏，但仍保留在 DOM 中供抽屉与账号操作复用。系统返回键依次关闭网页弹层、按网页路由返回上级，根页面回到课表后再退出。旋转、深浅色、字体大小变化不重建 Activity，WebView 会话不会丢失。
- **显示比例与字号**：原生界面和 App 里的网页都不跟随系统的“字体大小”，文字固定为设计字号（课程卡片上的字另有“课表设置 → 文字大小”）。屏幕短边不到 384dp 的手机（常见的 360dp，或把系统“显示大小”调大后的 320dp）按 393dp 宽的手机来排版再整体缩小，最多缩到 0.84，一屏内容和 iPhone 一样多；更宽的手机和平板不变，横屏、分屏时比例不变。原生这边由 `CpuTheme.kt` 的 `NativeScale` 完成；底部弹窗、对话框、下拉菜单各是独立窗口，会从系统的比例重新开始，所以一律用 `CpuWindows.kt` 里的 `CpuBottomSheet`、`CpuAlertDialog`、`CpuDropdownMenu`、`CpuDialog`，不要直接用 Material 的同名组件（`android/tests/native-scale.test.mjs` 会检查）。网页这边由站点的 `web/public/appearance-bootstrap.js` 改写 viewport 完成，随网站部署生效，已装的旧版 App 也有效。桌面小组件的文字用 dp，不随系统字号放大。
- **登录门禁**：未登录时显示原生登录页（统一认证、验证码、保持登录；长按图标解锁站内账号登录；须同意隐私政策与用户协议）。登录仍由网页的 Pinia 登录流程完成，HttpOnly 会话 Cookie 留在 WebView 中，原生不保存学校密码。判定与 iOS 相同：以网页登录状态为准，空账号报告先二次核验，Cookie 仅换取有限的恢复窗口，教务授权失效不会触发站点登录门禁。
- **原生课表**：两排工具栏（学期、日/周/月视图、回到本周今日、更多），周次切换与校历日期，周视图左右滑动切周、日视图左右滑动切换日期，12 节时间轴（优先使用校历下发的节次时间），连续节次合并，下拉刷新。月视图是一张月历：每天一格（公历日、农历或节日、课程圆点、休/班），左右滑动换月，上下滑动看下面所选那天的当天安排（课程和日程），可跳到日视图。点课程打开速览（教室、老师、周次、备注），“编辑”进入编辑器。今天这一列标出当前时间，日视图显示正在上、下一节和已结束；可在“课表风格”里关闭，也可隐藏周末（周末有课或补班的那一天仍显示）。已显示的课表不会被状态页替换：教务授权失效、刷新失败都以顶部横幅提示。
- **课表风格**：与 iOS 4.14 相同的六种风格——经典（原来的样子）、简约（默认；2026-11 起存着的经典一次性换成简约，之后再选经典就保留）、格子、表格、素笺、站牌，覆盖周、日、月视图；风格只换画法，不改课程数据、配色和背景。日视图顶部的七天条由各风格按自己周视图表头的样子画（经典保留原来的），选中的那天和今天各有各的标记：简约是浅色圆角底，格子是带边框的方格，表格是整格主题色，素笺是淡染，站牌是反色块（今天用底边粗线）。站牌只在时间和日期上用等宽字体，课程名、教室这些正文用系统字体。主题色按配色取一次并调到在画布、面板和今日列上都不低于 4.5:1。
- **重叠课程**：同一时段的课程并排显示；在编辑器里打开“优先显示这门课”后，重叠的节次只显示它，其余课程保留没被盖住的节次。优先级按课程名保存在课表修改的 `priority` 字段里（`server/src/shared/schedulePriority.ts`），和 iOS 共用。
- **缓存**：内存缓存 12 小时、最多 4 个学期；整学期规则只缓存一次，旧服务端的逐周数据由网页桥后台预取并推入原生缓存。最近一次成功的课表写入不参与备份的私有目录，并记录站点会话 Cookie 的指纹；冷启动先核对指纹再显示，随后静默刷新。账号变化或退出登录立即清空内存与磁盘缓存。
- **个人课程**：原生添加、修改、隐藏、删除、恢复教务原始安排与恢复已隐藏课程，经网页同源接口与 CSRF 保存，并核对服务器修改基线以避免覆盖并发编辑；研究生课表沿用网站限制。一门课可以有多组上课时间，节次可以不连续；保存时每段连续节次写成一条原有格式的修改项，其他客户端照常读取。与已有课程时间重叠时只提示，不阻止保存。
- **共享课表**（更多 → 共享课表）：为当前学期生成、更新、撤销分享码（每学期一个，走 `/api/schedule-shares`，需要已部署 `a9d92248` 之后的服务端才能列出自己的码、原地更新和免凭据撤销）；输入分享码或粘贴链接，预览后加备注导入。导入的课表整份保存在本机不参与备份的目录、按账号隔离，以只读方式打开，不进入小组件和冷启动缓存；对方更新后自动换新，撤销后保留副本并标记。iOS 的“关心”依赖实时活动，安卓没有对应功能。
- **日程**（`AgendaRemote.kt`、`ScheduleAgenda.kt`）：和网页 `/agenda`、药大拾间 NEXT 是同一份，存在站点 `/api/next-sync` 的 `agenda` 集合里。App 经网页桥 `CPUTimeNativeAgenda` 用 WebView 的登录会话读取和勾选，不另做登录。周视图按钟点画在当天那一列（和课程同一时段时是课程右边框上的一条细条，课程速览里列出），日期表头有圆点，日视图上方列出当天的日程，可直接勾选。新建和修改在课表上的原生表单里（见下文「与网页的协议」）。读到的列表存在 `files/agenda-cache.json`，冷启动先画它。App 不在通知栏提醒：国产系统普遍拦截后台闹钟，提醒只走服务器的站内通知和微信／QQ 转发；更新后首次启动删掉旧版留下的“日程”通知渠道。退出登录时清空，换账号后换成新账号的。
- **与 iOS 对齐的 NapTable 功能**（iOS 4.18 (81)、4.19 (82) 那一批）：
  - **点课程**（`ScheduleCourseMenu.kt`、`ScheduleOccurrences.kt`）：课程卡片没有长按，所有地方都是点一下打开课程速览，课程的操作都在速览底部：自己的课是「编辑整门课」（主按钮）和「调整这一次」「这次停课」（红色，先确认）；调过的课有「调」标记，速览里是「再调整这一次」「恢复原安排」；停课的那节留在原位变淡、标「已停课」，点开速览是「恢复这节课」；TA 的课、共享课表和本周不上的课只读，没有操作。这节课的日程和「＋ 添加」在速览的日程一栏。「调整这一次」选学期内的日期（放假、补班日不行）、先点开始再点结束的节次、教室和备注，和别的课冲突只提示。站点在快照里下发 `occurrenceChanges` 和每门课的 `editKeys`，保存走随包编辑桥 `CPUAndroidEditor` 的 `occurrence` 动作（只替换这一节的几条，其余保留，见 `server/src/shared/scheduleOccurrences.ts`）；快照没有这个列表时两项不出现。
  - **叠加到我的课表**（`ScheduleOverlay.kt`）：把任意一份已保存的共享课表叠在自己的课表上（代替情侣课表），周次标题下第二行写「叠加了 某某 的课」和对方学校，带关闭按钮。别的学校的课按钟点放到自己的节次上，保留真实时间（`OverlayTiming`）；共享课表和情侣快照带上学校名和对方自己的作息。叠加或情侣课表打开时，周视图换成几天并排的双栏日条：左边自己（实心卡片）、右边对方（空心描边卡片），节次轴固定、按天吸附滑动，最左那天跟着周次和选中的日子走；半栏里重叠的课合成一张带「+N」的卡，一起上的课有小爱心。
  - **找共同空闲**（`ScheduleCommonFreeSheet.kt`、`ScheduleMeetings.kt`）：和情侣、保存的共享课表比，选日期、至少空出多久（30 分钟–3 小时）和白天／晚上／全天，按天列出空闲时段和当天的忙闲条，可以一键建日程。各自按自己的校历和作息（调休、停课、调课都算）按钟点比较。
  - **速览与月视图里的日程**：课程速览列出「这节课的日程」（当天在这节课时间里、或标题／备注提到课名的），可勾选、可添加；月视图点一天在下面显示「当天安排」（课程和日程、添加日程、日视图）。和课程同一时段的日程改成课程右边框上的细条，不再盖住课名。
  - **背景**：「课表设置 → 背景图片」分浅色模式和深色模式，深色没有单独设置时沿用浅色；「调整范围」按屏幕比例拖动、双指缩放（最多 5 倍）、三分线、还原，选的范围按原图比例保存，原图留在本机可以重新调整。
  - **更多**：改成和 iOS 一样的面板：刷新、添加课程、添加日程、分享四个快捷按钮，下面是「日历与日程」「一起看」「外观与设置」三组。「导出整学期日历文件」按停课、调课和调休导出整学期（补班日写「调休补 某日 的课」）。没有做 iOS 那样直接写入系统日历：需要日历权限、本地账户，各家日历 App 行为不一，导出的文件各家都能导入。
  - **分享这一天**：「分享」可以把这一天做成竖版卡片图片（课程按时间排、停课划线、调课标注），也可以照旧把这一周以文字分享。法定节日（清明除外）当天没课时显示节日问候，第一次打开放一次烟花，点礼花按钮再放；系统关闭动画时不放。
  - **上课闹钟**（`ScheduleAlarms.kt`）：早上第一节课前（提前 30 分–1.5 小时）、午休后第一节课前（提前 10–30 分；上午的课上到下午时不响），按接下来 7 天的实际课程计划。闹钟交给系统时钟 App（`ACTION_SET_ALARM`，不打开时钟界面）：国产系统普遍拦截应用自己的后台闹钟，系统时钟最可靠。系统时钟只能按星期几重复，所以每个星期几按接下来这一周设一个每周重复的闹钟，单双周或放假改变时回来再点一次；同时间同标签的闹钟时钟 App 会复用，不会越点越多。
  - **桌面快捷方式**：长按图标有「今天的课」「添加日程」「日程与待办」「找共同空闲」（动态快捷方式，换包名的测试版也能用）。
  - **小组件风格与日程小组件**：课表小组件跟随课表风格，也可在「桌面课表小组件」里单独选（经典、格子、简约画法相同；表格加外框，素笺有纸色、衬线字、横线和红边线，站牌有自己的配色、等宽数字和顶部粗线）；可设小组件背景照片（缩到 900 px，上面盖一层可调浓度的底色）。新增「日程与待办」小组件：逾期待办、两周内的日程、没有日期的待办，点圆圈直接勾选，先记在本机，下次打开 App 并登录时经网页保存。
  - 实时活动、控制中心、聚焦搜索是 iOS 独有，没有对应。
- **样式与导出**：九套 Web 主题配色（由 `web/src/components/jwxt/scheduleTheme.ts` 生成）、相册背景（22%–88% 显现，默认 76%；Android 12 起支持 0–18 柔化）、深浅色，所有主题的课程文字对比度有回归检查。可按所选周以文本分享、导出 ICS 日历（北京时间，不含订阅地址或登录信息）。
- **图片**：网页图集交给原生查看器，支持左右切图、双指缩放、双击放大、下滑关闭和保存到相册。
- **网页权限**：仅对本站页面按需申请相机、麦克风；文件选择沿用系统文档选择器。
- **客户端统计**（`ClientStats.kt`，后台“安卓客户端”页）：启动、回到前台和账号变化时上报品牌、型号、系统与 WebView 内核版本、客户端版本，以及小组件、外观、课表风格、自定义背景、安装应用权限的状态；另按天汇总冷启动次数与耗时、网页进程崩溃或被回收、系统记录的进程退出原因（Android 11 起），一天结束后上传。未捕获异常的调用栈写入本机，下次启动上传；ANR 只上传系统转储里的主线程。安装标识是本机生成的随机 UUID，不读取 Android ID、IMEI 或广告标识；请求带 WebView 的站点会话，所以登录后安装会关联到账号。任何失败都静默，不影响使用。连正式站点的 Debug 构建不上报，指向开发服务器（`-PappUrl=`）的 Debug 构建照常上报，便于联调。

## 桌面小组件

临近课程 2×2 / 4×2、今日课表 4×2 / 4×4、两日课表 4×4，以及日程与待办 4×2，与 iOS、HarmonyOS 的样式族一致；课表小组件跟随课表风格（或单独指定），可设背景照片；支持九种主题和系统深浅色，完成的课程变灰，较大卡片标注剩余课程数。

- 原生课表加载后按日期展开写入本地，小组件优先读取这份课表；课表“更多 → 桌面课表小组件”可预览、选择主题、刷新并添加到桌面，也可编辑已添加实例的显示选项。
- 已有本地课表时不自行请求服务端；只对尚无本地数据的旧安装保留订阅接口回退，不复制登录 Cookie。上下课、换日和兜底刷新由系统调度，账号变化清理旧课表和订阅。完整规则见 [小组件显示规则](../docs/schedule-widget-rules.md)。
- 点击小组件打开原生课表并回到本周今日。
- **文字大小**（iOS `350e5e1c`）：“桌面课表小组件 → 文字与排版”选自适应、小、标准（默认）或大，每个小组件的编辑页可以另选（默认跟随 App）。大小是整块内容一起缩放的：内容排在 `1 / 比例` 大小的画布里再放大回去（`ScheduleWidgetCardRenderer.Frame.scaled`），字、色条和间距同一个比例，四周 16 的留白和背景不动；里面按高度挑排法的梯子照常工作，放大后放不下的课收进“后面还有 N 门课”，不会挤出去。“自适应”从 1.16、1.08 往下试，最满的排法放得下、没有字被截成省略号、周次没被挤掉才用，否则是标准大小（`ScheduleWidgetProvider.painterAt`）。日程小组件是系统排的文字，只跟小、标准、大，“自适应”按标准。
- **倒计时与进度**：临近课程的“当前 / 下一节”右边是“距下课 23:10”“距上课 12:40”，正在上的课下面有一条进度（临近课程的一栏、列表行、时间线卡片）。倒计时的数字是布局里的 `Chronometer`，由系统自己走，小组件不为它刷新：图里只留出位置（`Frame.countdown`），`showCountdown` 用两层 `weightSum` 按比例把它摆上去，不依赖桌面报的尺寸；App 里的预览把这一刻的数字直接画进图。“距上课”在上课前一小时出现，那一刻有一次刷新。`Chronometer` 数到 0 不会自己停，所以倒计时的终点另由 `countdownStepAt` 逼近：闹钟不要求准时（系统把窗口放宽到离现在的 0.75 倍），每次定在剩余时间的 0.55 处，最后 4 秒才定在整点上，到点换掉，晚不过 3 秒；只在桌面上有临近课程时才这样做。进度条画在图里，正在上课时每 5 分钟随刷新往前走一格。“上课倒计时与进度”可以关。
- **其余显示开关**：“隐藏已上完的课”（今日课表和两日课表今天那列不再把上完的课灰着留着；都上完时显示休息状态或“今日课程已结束”）、“时间线标出课间休息”、日期栏的“周次”和“最近节假日常驻”。都存在 `schedule_widget` 偏好的 `display` 一项里（`ScheduleWidgetDisplay`），旧版本没有这一项时取默认值。课程名称、教室、教师、时间、农历、节假日这六项仍在每个小组件自己的编辑页里。
- **日期栏**：中号、大号整宽的日期栏把最近法定假期的倒计时（“距元旦还有 49 天”）放在“第 N 周”下面，两行靠右；小号和两日课表的半宽列不显示，下面是休息状态时也不显示。
- **下一次课预告**：大号今日课表今天的课都放得下、底下还空着时，接着列下一个有课日开头的几门（标注“明天 周四”，字小一号），连一门都放不下时退成一行“08:00 药物设计学 等 2 门”。时间线只在今天一两门课时预告，列表放得下就预告；选了“只看今天”不预告。

## 与网页的协议

UA 追加 `CPUWebScheduleApp/<versionCode> CPUWebScheduleAppVersion/<versionName> CPUTimeNative/1`。`CPUTimeNative/` 让网页按原生外壳处理（`/schedule` 路由交给原生、同步未读数、安装共享课表桥 `web/src/utils/iosNextScheduleBridge.ts`）；`CPUWebScheduleApp` 让网页和服务端继续把它识别为 Android，而不是 iOS。

- `app/src/main/assets/NativeShellBootstrap.js`：页面开始时注入（仅本站来源），隐藏网页栏、创建 `window.CPUTimeNative` 并上报路由、登录状态与外观。消息优先经按来源限定、只接收主框架的 `WebMessageListener` 送达 Kotlin；旧版 WebView 回退到 JavaScript 接口。
- `app/src/main/assets/NativeWebCompatibility.js`：由 `android/bridge/*.ts` 生成，页面加载完成后执行。线上网页尚未提供课表桥时，用现有 Pinia 状态和同源 Cookie 安装兼容桥，并提供原生登录、顶栏状态、返回导航、弹层检测与课程编辑（`CPUAndroidEditor`）。
- 原有 `CPUAndroid` 桥（应用内更新、小组件、图片保存）保留，仅对本站页面开放。
- 应用更新（`AppUpdater.kt`、`update/`、`AppUpdateSheet.kt`，从药大拾间 NEXT 移植）：回到前台时每 6 小时最多检查一次 `/api/site/downloads/android?from=<已装版本>`，有适用的增量包（`.cpupatch`，DEX 不压缩存放才小）就只下载它并用已安装的 APK 合成，否则下载完整包；默认 Wi-Fi 下自动下载，5 MB 以内的增量包用流量也自动下载。校验通过后 Android 12 及以上已授权安装时离开 App 约 10 秒自动安装，其余情况打开一次“应用更新”面板，面板里也可以选完整包；在面板里点一次“立即更新”就下载并直接安装，不再停在“已准备好”。网站发现线上有更新的版本时调用 `CPUAndroid.checkNativeUpdate()` 让 App 立刻在后台检查（不受 6 小时间隔限制），只在需要用户操作时打开面板。安装后系统会关闭 App，不会自动重新打开（Android 10 起后台不能启动界面）。网页更新弹窗经 `supportsNativeUpdater` / `openNativeUpdater` 把手动更新交给它，强制更新期间网页弹窗照旧显示。Release 用 R8 只做裁剪（`proguard-rules.pro`：不混淆、不优化，未变的类字节不变）；`-PminifyDebug=true` 让调试版也跑裁剪后的代码。
- 日程经网页的 `CPUTimeNativeAgenda`（`web/src/utils/nativeAgendaBridge.ts`，`list` / `toggle` / `save` / `remove` / `relay` / `parse`）读写，在课表里原生编辑（`ScheduleAgendaSheets.kt`）：点日程打开编辑器，点空着的节次可选「添加日程」或「添加课程」，「更多 → 日程与待办」列出待办、接下来一周和「微信和 QQ 也提醒」。列表变化时网页调用 `CPUTimeNative.agendaChanged()`，App 重新读取；站内的 `/agenda` 链接经 `CPUTimeNative.openAgenda` 在课表上打开。线上网页还没有这个桥时保留上次读到的。

修改 `android/bridge`、共享课表桥或网页主题后，在仓库根目录运行：

```sh
npm ci --prefix web
npm run android:generate
node --test android/tests/*.test.mjs
```

Linux 部署工作流会检查这两个生成文件是否过期，并运行上述测试。

## 发布构建

共享 WebView 默认加载：

```text
https://cputime.cn/home
```

本地 release 编译检查（不是正式生产制品）：

```bash
./gradlew :app:assembleRelease
```

正式分发必须给 GitHub CI 的 unsigned APK 使用已有发布证书签名；不能新建自己的 keystore 替代，否则无法覆盖安装。签名环境、校验和上传步骤见 [发布操作手册](../docs/android-release-runbook.md)。不要把 keystore、密码或签名配置提交到仓库。

正式更新使用 `Android release artifact` 工作流生成的精确提交 APK，下载后使用现有发布证书签名，并核对包名、版本号和证书摘要。先上传企业盘原发布目录并下载回读校验，再更新网页版本信息、等待精确提交的 `Linux deployment artifact` 成功并部署。仓库中的 APK 仅留存发布记录，不作为网站或 ESA 的下载来源；稳定下载入口及旧 APK 链接都通过企业盘分发，解析失败时提示重试。

V37 将下载包复制到独立缓存并验证包名、版本和签名，通过 FileProvider 授予安装器读取权限。Web 仅对 V37 及声明 `supportsStagedApkInstall` 的客户端启用应用内更新；旧版打开普通 `/download` 页面交给系统浏览器，避免旧壳拦截 APK 链接。3.x 旧版会收到一次修复引导，手动更新入口始终可用。

V38 支持保存下载任务和待安装文件，重开应用后恢复进度、继续安装或重试。正式版本由 `server/src/releases/android.json` 管理，发布门禁与真机验收步骤见 `docs/android-release.md`。
