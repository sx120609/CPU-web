# 智慧树在线工作台

入口：`/services/tools/zhihuishu`。校园小工具和桌面工具介绍面板均有链接。

## 本次实现

- 复用 CPU-web 登录和 `/course-bot` 的鉴权边界，新增 Vue 工作台。
- 知到扫码、共享课/校内课列表、搜索多选、开始、进度与停止。
- 每个用户一个 Python 子进程，Cookie 仅驻留进程内存；使用独立临时目录。
- 服务器只接收课程 key，并从该用户已获取的课程列表解析 ID；不接受用户指定命令、脚本、URL 或其他人的 userId。
- Node 通过 JSONL 和 Python 通信，原始日志、请求头、Cookie 和一次性登录码不回传也不写日志文件。
- 任务错误、验证码、扫码超时、运行超时均显示明确状态。部分上游循环会吞异常，适配层会阻止误报成功。
- Python 源码在构建时复制进 `server/dist/python/zhihuishu`，随现有 `server-dist.tar.gz` 产物交付。
- 右上角外观切换：浅色、深色、跟随系统（默认）。偏好保存到当前浏览器；跟随系统通过 `prefers-color-scheme` 变化事件自动更新，跨标签页同步偏好，页面卸载后移除监听。主题覆盖工作台、管理员页、本地历史和浮窗，二维码保留白底。

## 首版范围与限制

支持共享课和校内课；不暴露上游 AI 课程、考试和外部推送。默认 1 倍速，可在工作台选择 0.5、0.75、1、1.25、1.5、1.75、2 倍速，开始任务时生效，运行中锁定。后台按倍速推进进度，实际耗时受请求和暂停影响。完成阈值为 1.0。

## 视频弹题与管理员设置

### 活动记录与本地历史

校内课遍历中，叶节点 `dataType is None` 会记录实际跳过的条目名称，标注“不支持的条目，可能为练习/习题；未作答、未提交”。不把未知类型断言成已确认的习题。共享课只遍历视频，故在每门课程开始时记录“独立课后习题、章节练习未检查、未处理”，不虚构题目清单。

活动使用服务器生成的唯一 ID，包含时间、消息和类别。服务器保留本次会话最近 500 条消息；浏览器每次同步按 ID 去重，存入 localStorage，按当前站点及 CPU-web 账号隔离，保留最近 5,000 条。新增“本地活动记录”页，支持搜索、仅练习提醒、分页和导出 JSON；保存失败显示明确提示，不能误称保存成功。不会持久化二维码、Cookie 或登录凭据。

刷新、断开、重新扫码后，已保存的本地记录保留；清理站点数据会删除本地记录。页面关闭期间不能写入浏览器，重开后仅能补收服务端尚未清理的会话记录；不承诺完整离线采集。服务器重启及会话过期前未同步的消息可能丢失。记录功能从更新后开始生效，历史跳过条目不补造。

上游 `fuckZhidaoVideo` 读取弹题时间点，在相应进度调用 `lessonPopoupExam` 取题；`answerZhidao` 从 `questionOptions` 选择 `result == '1'` 的选项，约两轮循环后调用 `saveLessonPopupExamSaveAnswer` 提交。这个弹题流程不使用 AI；是否仍能拿到正确标记取决于平台接口。

新增“管理员”选项卡，弹题自动作答、弹题自动提交均默认关闭。关闭作答时遇题停止；仅开启作答时允许选择答案，但提交被拦截并停止；两项都开启才沿用上游提交流程。关闭状态不会绕过弹题继续报告任务完成，需到官方页面处理后重新连接。学习进度上报不受题目提交开关控制。

生产接口依赖 CPU-web 的 `authRequired` 从数据库加载角色，仅 `req.user.role === 'admin'` 可保存设置；普通用户不能通过任务参数覆盖策略。本机单用户试用入口使用固定管理员身份，只监听 127.0.0.1，不属于生产鉴权配置。

设置保存在单个服务器进程内，对全部在线助手用户生效；重启恢复关闭。修改设置时停止所有正在运行的任务并清除它们的会话，避免旧进程继续使用旧策略。空闲会话在下次任务启动时读取新策略。

上游另有 AI 测验、`ExamCtx.saveAnswer` 和 `submitExam` 代码，网页没有提供相应入口；适配层明确拒绝 `fuckAiCourse`。管理员开关仅针对视频弹题，不会启用考试或交卷。

当前视频百分比来自脚本进度回调，不代表智慧树已确认的学习记录。“已处理课程”也不是课程达标证明；任务结束后需要在智慧树核对。

右下角实时状态浮窗可收起，约每 2.5 秒同步一次。展示当前内容、脚本百分比、倍速、已处理课程数及最近同步时间；执行端另报告视频推进、随机暂停倒计时、读取弹题、提交答案和上报进度的等待阶段。超过 20 秒没有执行端新状态时提示等待或重试，页面断线时明确标注为最后收到的状态。暂停倒计时不会替换视频百分比。该显示用于定位等待原因，不证明平台记录已经入库。

停止会终止该用户的进程并清除登录会话，继续时需重新扫码。网页关闭后任务继续；单次任务最长 2 小时，空闲会话 30 分钟后清理，扫码期限为 3 分钟。默认最多同时存在 8 个活动会话，包括等待扫码及已登录空闲的会话。

**首版要求由单个 Express 进程承接这些接口。** 状态保存在进程内存，不支持 PM2 cluster、多副本随机负载均衡、跨进程续跑或重启恢复。蓝绿发布切换及服务重启会结束会话；不要对外承诺发布期间任务无中断。后续要扩大并发，应迁移为独立任务服务与持久化队列。

## 应用补丁

在 CPU-web 的独立工作分支中应用交付包的 `cpu-web-zhihuishu.patch`：

```sh
git apply --check /absolute/path/to/cpu-web-zhihuishu.patch
git apply /absolute/path/to/cpu-web-zhihuishu.patch
```

补丁基于 2026-10-17 读取的公开 main 分支文件制作。检查失败说明当前分支存在差异，需要按具体冲突合并；不要覆盖整个项目。包中的 `changed-files/` 供审阅和手工合并，不建议直接覆盖已有同名文件。

## 安装 Python 执行环境

本次已用 Python 3.12 实测适配层启动及测试。推荐在服务器建立稳定路径的独立虚拟环境，避免放入会被蓝绿部署替换的版本目录。

```sh
python3.12 -m venv /absolute/stable/path/zhs-venv
/absolute/stable/path/zhs-venv/bin/python -m pip install -r server/python/zhihuishu/requirements-lock.txt
```

`requirements-lock.txt` 固定本次验证使用的依赖版本；运行环境的平台与 Python 版本不同时仍需重新验证。`requirements.txt` 记录直接依赖的允许范围。

给 CPU-web 后端进程配置：

```dotenv
ZHS_WEB_ENABLED=true
ZHS_PYTHON=/absolute/stable/path/zhs-venv/bin/python
ZHS_MAX_SESSIONS=8
```

缺省关闭在线执行；未启用时页面显示“尚未启用”。这里不需要阿里云盘 API Key，也不需要用户提供智慧树密码或模型 API Key。

## 检查与生产发布

在完整仓库根目录：

```sh
ZHS_TEST_PYTHON=/absolute/stable/path/zhs-venv/bin/python \
  node --import ./server/node_modules/tsx/dist/loader.mjs --test server/tests/zhihuishuRunner.test.ts server/tests/zhihuishuRoutes.test.ts server/tests/zhihuishuHistory.test.ts
/absolute/stable/path/zhs-venv/bin/python -m unittest discover \
  -s server/python/zhihuishu -p 'test_*.py' -v
npm run build:compile --prefix server
npm run build --prefix web
```

测试使用模拟上游，不访问真实智慧树账号。正式验收先由用户扫码，检查其本人课程列表，再选择一门课程验证开始、进度和停止。若上游已改接口，需修复对应适配后再启用。

生产推送与部署遵循仓库 `AGENTS.md` 和 `docs/production-requirements.md`：等待确切 commit SHA 的 Linux deployment artifact 构建成功，核验绑定该提交的产物，再按项目流程部署。交付包不是生产构建产物，本次未执行 GitHub 推送或线上部署。
