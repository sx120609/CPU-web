# 宿舍课表

宿舍课表是课表页（`/schedule`）「更多 → 宿舍课表」里的一个弹窗，不是单独的页面，也不往周视图网格上叠东西。和情侣课表的区别只有两点，但都很要紧：

- 一条宿舍关系里可以有多个人（默认 6 人，上限 8 人，对应 8 种成员颜色），宿舍码可以被多名室友重复使用；情侣码是一次性的。
- 宿舍课表读的是所有人上传的课表快照，看重的是「什么时候大家都有空」和「谁哪天要早起」，所以不画整张合并网格，只给空闲时间块和早八名单。

两套能力完全独立建表，所以同一个账号可以同时有一条情侣关系和一条宿舍关系。`DormMember.userId` 是主键，保证每个账号同时只在一个宿舍里。

## 绑定

- 还没有宿舍时，「我建宿舍」会创建宿舍并生成宿舍码（6 位，字母表 `A-Z 2-9` 去掉 `I`/`O`），自己成为创建者（舍长）。宿舍码 24 小时内有效，可以被多个室友重复使用；宿舍满了之后自动作废，换码由舍长操作。
- 其他人在「用宿舍码加入」里输入宿舍码即加入。加入时先锁定宿舍行，再重新检查邀请码、有效期和人数上限；最后一个名额用完后清除邀请码。
- 账号同时在两个宿舍里会返回冲突并提示先退出。自己未被接受的邀请不存在，所以不需要像情侣课表那样清理悬空关系。
- 退出宿舍只删除自己那一行，快照随之级联删除；舍长退出时身份转给最早加入的室友，最后一个人退出时整条关系删除。舍长也能把某个成员移出宿舍，被移出的人会收到站内通知。
- 注销账号时 `accountDeletion` 会调用 `deleteDormDataForUser`，先摘掉自己，宿舍空掉时整条删除。

成员操作按「当前用户事务锁 → 宿舍行锁」的顺序执行。退出、移出、换码、换色和快照读写都在拿到锁后重新读取成员与权限，避免使用已经过期的成员列表；账号注销复用同一套锁和舍长转交逻辑。

## 成员颜色

颜色一共 8 种（蓝、粉、紫、青、绿、黄、橙、红），存在成员上（`DormMember.color`），所有人看到的一致：

- 自己选过颜色就用自己选的；没选过的成员按加入顺序自动分配还没被占用的颜色，所以任何时刻都不会出现两个人同色。
- 选了别人正在用的颜色就是两人互换，和情侣课表的规则一致。
- 服务端的 `dormMemberColors` 和 `dormSwapColors` 是唯一实现，接口返回的颜色都从这里算。

## 课表同步

服务端不保存教务课表，宿舍课表读的是每人各自上传的快照（`DormScheduleSnapshot`，每人一行）：

- 课表页（`Schedule.vue`）加载成功 4 秒后，若账号在某个宿舍里，就把**当前学期**完整课表（含自定义修改）和校历上传。翻看往年学期时不上传。
- 页面只有单周数据时需要再向教务请求整学期课表，因此同一份自定义修改最多每 6 小时拉取一次；内容指纹没变时最多每 12 小时刷新一次「同步于」时间。
- 不在宿舍里的状态在浏览器里缓存 10 分钟，避免每次打开课表都查询服务端。加入或退出宿舍后会立即同步一次。
- 服务端对快照做与「分享课表」相同的校验（最多 600 门课、512 KB），内容哈希相同时只更新 `syncedAt`。

## 页面计算

计算全部集中在 `web/src/views/schedule/dorm.ts`，是纯函数，有单元测试覆盖；弹窗在 `DormDialog.vue`。

空闲查询（`dormDayAvailability`）：

- 时间窗从所有成员的节次表推出最早开始到最晚结束，再按 5 分钟取整；一个人都没有节次表时退回 08:00–21:40。
- 按所有人课程的开始/结束时间把时间窗切成小段，每段统计谁没有课，再按「这一段谁有空」合并相邻的段，输出的是一整块连续时间，不是零碎节次。
- 默认要求所有有数据的成员都有空；也可以指定「至少 N 人有空」。明确指定的人数不会因数据缺失而降低；少于 20 分钟的空档默认不显示。
- 当天没有课表数据的成员（没同步或不在学期内）不算有空也不算有课，只单独提示，不会把「不知道」当成「没课」。

早八（`dormMorningDuties`）：

- 口径和情侣课表一致：**占用第 1 节**就算早八。自定义了开始时间的课仍按第 1 节的判断为准，所以把课改到 07:40 的第 3 节课不算早八。
- 早八清单按未来 7 天逐天列出，并单独给出「今天/明天谁要早八」的一行提示；课表没同步的室友不会出现在名单里，只标记为可能不全。

## 接口

全部需要登录，挂在 `/api/dorm`：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 当前状态：`none` / `active`（含宿舍名、容量、成员、自己的资料；邀请码只返回给舍长） |
| POST | `/invite` | 创建宿舍（还没有宿舍时）或生成、更换宿舍码；只有舍长能换码 |
| DELETE | `/invite` | 取消宿舍码 |
| POST | `/join` | 用宿舍码加入（每 IP 10 分钟 15 次） |
| PATCH | `/` | 改宿舍名（仅舍长）或自己的颜色（`myColor`：`DORM_COLORS` 之一） |
| DELETE | `/` | 退出宿舍 |
| DELETE | `/members/:userId` | 把成员移出宿舍（仅舍长） |
| PUT | `/schedule` | 上传自己的课表快照 |
| GET | `/schedules` | 读取全宿舍的课表快照 |

## 测试

- `server/tests/dormSchedule.test.ts`：宿舍码字母表与输入容错、宿舍名规范化、颜色分配与互换、容量常量。
- `web/tests/dormSchedule.test.ts`：时间窗推导、空闲块合并与最短门槛、放宽人数条件、无数据成员的处理、学期外日期、早八判定（含自定义时间不算早八）、日期与分钟格式化。
- `web/tests/dormSync.test.ts`：宿舍状态和同步缓存、加入/重新加入后的首次上传。
- `server/tests/dormSchedulePostgres.test.ts`：使用真实 PostgreSQL 的行锁屏障验证抢最后一个名额、邀请码撤销、同时加入不同宿舍、并发退出与舍长转交，以及权限、快照隔离和级联删除。设置 `DORM_TEST_DATABASE_URL` 为本机隔离数据库、schema 为 `dorm_test` 后运行；测试会创建表并清理自己的数据。GitHub `Linux deployment artifact` 工作流必跑此项。
- 纯计算和同步测试随 `npm test` 运行，数据库测试在未设置隔离数据库地址时跳过。

## 已知边界

- 只有网页端实现。情侣课表在安卓、鸿蒙、iOS 各有一份原生实现，宿舍课表暂未跟进原生端，原生壳里打开课表页看不到宿舍入口。
- 宿舍课表没有单独的站点功能开关，和情侣课表一样随课表页一起可用。
