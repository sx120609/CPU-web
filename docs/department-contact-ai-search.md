# 部门联系与拾间AI

部门联系页面对精确部门名、窗口名、记录ID或号码直接使用公开目录 API。口语及办事需求使用 `/api/search/assistant/department-contacts`，复用拾间AI配置的模型和服务，不引入额外服务。

语义搜索最多两次模型生成：先从真实资料分类中选择最多两类，再从该分类的真实候选元数据中选择最多8个ID。每类最多100条候选，合并最多120条；目前最大的分类有71条。候选只提供名称、业务、校区、特殊范围及是否有公开邮箱/线上入口，不提供号码，也不把整份通讯录塞入提示词。展示内容由服务器从同一目录记录解析，未知分类、候选外ID、额外号码/邮箱字段及澄清中的联系方式会被拒绝。分类、校区、是否含特殊资料在服务器限制候选范围。

语义搜索在现有 `/search/assistant` 认证和原生客户端访问限制下运行，与助手共用每分钟20次频率限制。一项搜索使用一次现有助手额度预留；模型多轮调用不额外计为用户请求。失败或客户端取消退回预留，成功的无结果或澄清属于一次正常请求。没有新增收费规则。页面只在提交时调用AI，并阻止待处理查询的重复提交、取消旧请求、忽略过期响应。同一页面查询结果的详情开关复用结果，避免再次使用额度。

校园助手始终获得目录工具指令，由模型自主决定校园服务问题是否需要查窗口，普通闲聊不强制查询。模型请求的字面查询无结果或候选过宽时，会复用语义搜索；用户原问题作为补充上下文传入。每轮最多3项查询、8条结果。仍然不自动拨号、发邮件或对外办事。

来源检查保持白名单。链接解析识别中文标点、引号、Markdown和本地详情链接，路径、查询参数与来源保持严格匹配。来源失败最多重答一次，使用相同的已查事实并要求由服务器附引用；再失败则拦截。普通、流式和既有修复路径使用相同校验。流式工具回答在通过校验前不向客户端发出。

查询“校长”时，保留原别名对应的缺口记录，避免展开成“校长办公室”后丢失“校长信箱”来源。现有资料仅确认校内IP访问的信箱入口，未核实公开电子邮箱；表单入口、部门邮箱、院长邮箱不得冒充校长个人邮箱。邮箱字段进入有界模型上下文并接受记录白名单校验。普通窗口不得称为未经来源证实的投诉专线。

回归覆盖“我要给校长发邮件”、“食堂吃出虫子怎么办”、宿舍漏水、校园卡遗失、来源标点、伪造URL/号码/邮箱/职责、候选外ID、特殊范围、普通闲聊和无结果。传输测试使用合成HTTP provider，覆盖Chat Completions与Responses的普通/流式路径；不作为真实模型理解的证据。真实模型、生产认证额度账本和原生真机尚未实测。
