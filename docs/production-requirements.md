# CPU-web 生产推送要求

## 适用范围

本要求适用于仓库的每一次远程推送，包括仅修改文档或工作流的推送。生产部署是独立操作；完成推送和编译不代表获得了部署授权。

## 推送前门禁

1. 只暂存本次任务文件，保留工作区中不相关的用户文件和生成物。
2. 先完成准备推送的最终提交，确认当前 `HEAD` 就是将要推送的提交，且已跟踪文件没有未提交修改。
3. 在仓库根目录执行：

   ```bash
   npm run verify:push
   ```

4. 该命令必须完整成功，覆盖以下三个生产构建目标：

   - Server：生成 Prisma Client 并完成 TypeScript 编译；
   - Web：完成 TypeScript/Vite 生产构建；
   - VoiceHub：完成 Nuxt/Nitro CPU 版本生产构建。

5. 任一目标失败都必须停止推送。修复并形成最终提交后，从头重新执行完整门禁；只做类型检查、只构建改动模块或沿用旧构建结果均不合格。

## 推送后门禁

1. 推送后记录本地完整提交 SHA，并验证本地 `HEAD` 与远端目标分支一致。
2. `main` 的每次推送都会触发 `Linux deployment artifact` 工作流。必须核对该工作流：

   - 检出的是本次推送的完整提交 SHA；
   - 在 Ubuntu 24.04、Node.js 24 环境中成功构建 Server、Web 和 VoiceHub；
   - 成功生成、校验并上传名称中含完整提交 SHA 的 Linux 制品。

3. 只有本地 `npm run verify:push` 成功、远端提交一致、精确 SHA 的 CI 工作流成功且制品存在，才可以报告“推送及编译完成”。
4. CI 仍在运行、失败、被取消、没有对应 SHA 的运行记录或没有制品时，必须明确报告未完成，不能把 `git push` 成功当作生产推送完成。

## 部署边界

上述流程只负责提交、推送、编译和制品验证。除非用户明确要求部署，否则不得执行 `deploy.sh update`、后台更新部署或任何生产发布操作。
