# 艾绒树洞

艾绒树洞是“艾绒”朋辈心理社在药大拾间里的匿名倾诉模块，入口在“校园服务”和 `/treehole`（可做成二维码对外分发）。它提供同学之间的倾听陪伴，不属于专业心理咨询；危机个案引导到学校心理发展中心。

## 角色

| 角色 | 身份来源 | 能做什么 |
| --- | --- | --- |
| 来访者 | 任何登录的在校同学（默认要求学校统一身份认证账号） | 发起一对一倾诉、申请加入宣泄室、查看自己全部历史、结束对话、自愿留下联系方式 |
| 洞主（小艾绒） | `TreeholeStaff.isHost`，有两位编号 `hostCode` | 排班内自动在岗、手动上下线；接待自己的会话、打标签、提交高危转介；推荐宣泄室；联名新建宣泄室；进入宣泄室成为群管理员并审核入群、撤回消息、移出成员 |
| 核心管理员 | `TreeholeStaff.isAdmin` | 查阅全部会话（只读）；跟进高危工单、追加备注；实名溯源的提交与审批；人员任免与排班；关闭宣泄室；统计；操作日志；树洞设置 |
| 站点管理员（运维） | `User.role = admin` | 只能任免树洞人员、录入排班，看不到任何会话、工单、统计和日志 |

树洞身份独立于站点身份：站点管理员不自动拥有内容权限。一个人可以同时是洞主和核心管理员。停用的人员不能再打开任何会话，包括自己接待过的。

## 启用步骤

1. 站点管理员在 `/treehole/admin` 用学号任命第一位核心管理员。
2. 核心管理员任命其余核心管理员（心理中心对接老师等）和洞主，给洞主录入每周排班（北京时间，同一天不重叠、不跨零点）。洞主编号 01–99，留空时自动分配；编号决定宣泄室虚拟 ID 前缀，不要随意改。
3. 在“设置”填写心理发展中心的名称、电话、地点、开放时间和引导文案。
4. 勾选“向来访者开放”。未开放时只有洞主和核心管理员能开启会话。

“校园服务”里的入口可以在小工具管理里按 `treehole` 隐藏。

## 知情同意

进入树洞首页必须先勾选知情同意，版本号是 `TREEHOLE_CONSENT_VERSION`（服务端 `treeholePolicy.ts` 与网页 `api/treehole.ts` 各一份，要同步修改）。版本号变化后所有人需要重新同意。未同意时不能开启会话、上传图片或申请入群。

## 一对一倾诉

- 两种模式：留言倾诉（`async`，可选任意在任洞主或交给系统安排，系统优先安排在岗、手头会话少的洞主）和实时聊天（`live`，只能选当前在岗的洞主）。
- 每位来访者同一时间只有一段进行中的倾诉；每天最多开启 6 段。
- 每段会话生成新的来访者虚拟 ID（`来访者 XXXX`），与账号和以往会话都没有关联；来访者结束会话后这个 ID 作废，记录保留在双方的历史里。只有来访者本人能结束会话。
- 消息支持文字和图片，不支持语音、视频、文件。网页每 2.5 秒（实时）或 6 秒（留言）刷新一次新消息，页面在后台时暂停。

### 在岗判定

在岗 = 洞主在任，且（在排班时段内且没有手动下线，或排班外手动临时上线）。

- 排班内点“暂时下线”：到本时段结束为止离岗，下个时段自动在岗。
- 排班外点“上线”：临时在岗两小时。
- 排班内点“上线”：撤销手动下线。

### 标签与高危转介

洞主可以把会话标成“普通情绪”“重点关注”“高危转介”。来访者看不到标签。

标记高危转介必须同时提交表单（危机类型、紧急等级、学生当下状态、洞主初步陪伴记录），表单不提交，标签不成立。提交后：

- 生成高危工单，立即以强提醒通知全部核心管理员；
- 来访者对话框上方常驻显示心理发展中心的求助渠道和紧急提示，来访者收到一条引导通知；
- 标签不能再改回，后续由核心管理员在工单里跟进（待处理 / 跟进中 / 已结案，可追加备注；状态和备注变化会通知上报的洞主）。

### 联系方式与实名溯源

- 方案 A（自愿）：来访者可以在对话菜单里自愿留下联系方式，只有接待洞主和核心管理员可见。
- 方案 B（审批溯源）：需要线下干预时提交实名溯源申请。洞主可以在高危表单里勾选“建议实名溯源”，核心管理员也可以在工单里提交。申请要两名不同的核心管理员同意才生效；管理员提交时本人算一票，洞主提交不算票。任何一名核心管理员都可以不同意，申请随即作废。
- 批准后核心管理员才能在工单里查看来访者的学号、学校认证状态、昵称、自报院系与入学年份、邮箱和最近登录时间。药大拾间不保存真实姓名和手机号。每次查看都记入操作日志。

## 情绪宣泄室

- 新建要至少 3 名洞主联名：一名洞主发起提议，其他洞主联名，第 3 人联名时自动建成，联名的洞主都是群管理员。之后任何进入宣泄室的洞主也自动成为群管理员。
- 来访者不能搜索或直接加入。接待洞主在一对一会话里发送宣泄室推荐卡片，来访者在卡片上提交申请（可附留言），由该宣泄室的群管理员审核；没有群管理员时由核心管理员审核。审核结果会通知来访者。
- 群内虚拟 ID = 推荐洞主编号 + 进群次序编号（至少两位）。例如洞主 01 推荐、第 67 位进群的来访者是 `0167`。次序编号在同一宣泄室内对当前成员唯一：成员退群或被移出后，空出的号优先给下一位新成员（下一位由洞主 03 推荐就是 `0367`）；没有空号时向后顺延。
- 来访者只能看到自己进群之后的消息。群里禁止交换联系方式和互加好友：来访者发送的手机号、QQ／微信号和“加我微信”一类内容会被拦下。
- 群管理员可以撤回消息、移出来访者、关闭宣泄室；洞主之间不能互相移出，需要核心管理员处理。撤回的消息成员看不到原文，核心管理员仍能看到。撤回、移出和关闭都会给核心管理员发违规记录通知，并记入操作日志。关闭后成员都无法再进入，记录留存在后台。

## 隐私与存储

- 来访者页面和洞主页面都不显示学号、姓名、昵称或头像；洞主只以“小艾绒 XX”出现。
- 一段会话只有来访者本人、接待洞主和核心管理员能看。其他人请求时一律按“会话不存在”处理。核心管理员只能查阅、不能发言，每次打开会话、工单、宣泄室都记入操作日志。
- 会话、消息、工单、宣泄室记录和操作日志永久保存。账号注销时，树洞记录保留，但账号本身被匿名化，记录无法再关联到本人；同时解除其树洞身份、知情同意、宣泄室成员关系和待审核的入群申请。
- 图片重新编码为 WebP（最长边 1600 像素），去掉 EXIF（含拍摄位置），只保存这一份，不保留原图。图片存在服务器私有目录 `server/runtime/treehole-images`（蓝绿发布的共用目录，可用 `TREEHOLE_STORAGE_ROOT` 改位置），不进对象存储和 CDN，按会话和宣泄室成员身份鉴权读取。网页里别人的图片默认模糊并显示风险提示，点开后才显示；不提供下载按钮。
- 树洞接口响应都带 `Cache-Control: private, no-store`，网页的通用 GET 缓存不缓存 `/treehole`。
- 树洞内容不送 AI 审核。

## 通知

树洞通知只走药大拾间的站内消息（分类 `treehole`，网页和各端 App 的消息中心都能看到），不转发到 QQ 和微信：第三方聊天软件里出现“树洞有新回复”本身就会暴露对方在使用树洞。通知只写事件和去向，不带对话内容。

| 收件人 | 事件 |
| --- | --- |
| 来访者 | 洞主新回复、宣泄室审核结果、高危求助引导、被移出宣泄室、宣泄室关闭 |
| 洞主 | 新的倾诉、来访者新消息、来访者留下联系方式、宣泄室入群申请、建群联名提议与建成、上报的高危工单有新跟进 |
| 核心管理员 | 高危告警、实名溯源审批申请与批准、宣泄室违规记录（撤回、移出、关闭） |

新消息提醒会避开正在看对话的人：对方 35 秒内还在刷新这段对话就不提醒；若对方其实已经离开，40 秒后仍没读到就补一条。同一段会话最多每 30 分钟再提醒一次。

## 代码位置

- 数据表：`server/prisma/schema.prisma` 里以 `Treehole` 开头的模型。
- 规则：`server/src/services/treeholePolicy.ts`（在岗、虚拟 ID、次序编号、联系方式拦截、溯源票数、提醒节流、会话隔离），单测在 `server/tests/treeholePolicy.test.ts`。
- 接口：`server/src/routes/treehole.ts`（首页、一对一会话、图片、洞主工作台）、`treeholeRooms.ts`（宣泄室）、`treeholeAdmin.ts`（后台），挂在 `/api/treehole`。
- 网页：`web/src/views/treehole/`，路由 `/treehole`、`/treehole/new`、`/treehole/session/:id`、`/treehole/room/:id`、`/treehole/host`、`/treehole/admin`。
